# Per-invocation overhead artifacts

Auxiliary timing evidence for the latency tier's **estimated per-invocation
overhead**, published under
[Amendment A24](../../../docs/latency-tier.md#amendments). These are **outside
the freeze**: `freeze/v1` binds normalized reports and one raw-evidence digest
per result, and does not digest anything here. Nothing in this directory is
read by the scoring path, by `validate-reports`, or by the freeze manifest.

## What the figures are

The wall-clock of **one complete adapter invocation over a trivial no-flow
fixture** — same pipeline, same committed policy, rule, query or config path,
same subprocess shape, and for a two-subprocess adapter both subprocesses. The
fixture declares the benchmark's own `dfb_source` and `dfb_sink` endpoints and
never connects them, so there is no flow to find and what the invocation costs
is very nearly all fixed cost.

That makes each number **fixed per-invocation overhead plus near-zero
analysis**: an *upper bound* on start-up and warm-up, labelled an estimate
everywhere it appears, and never subtracted from a cold number. It is a cold
single-shot execution — the same posture the cold rows are measured in, and
not a steady-state one.

Every figure is a **range over retained repeats**, the convention
[A21](../../../docs/latency-tier.md#amendments) established for the warm
marginal. The repeat count is a constant in the runner's source, every repeat
is retained below, and the range's width is the measurement's precision. There
is no agreement threshold: repeats that disagree widen the range.

## The files

One directory per adapter and fixture language:

| Path | What it is |
| --- | --- |
| `<adapter>-<language>/invocation-overhead.json` | Every repeat's wall-clock, its phase split, and the one-minute load average sampled immediately before it was spawned, plus the published range. |
| `<adapter>-<language>/fixture/` | The trivial no-flow fixture the measurement analyzed, retained verbatim beside its digest in the JSON. |
| `<adapter>-<language>/run-environment.json` | The environment stamp and the witnessed tool identity the measurement ran under. |
| `semgrep-kotlin/resolved-rule.yaml`, `opentaint-kotlin/resolved-rule.yaml` | The committed rule resolved against the fixture's endpoint names — the exact configuration analyzed, for the adapters whose configuration is per-case. |
| `flowdroid-java/resolved-sources-sinks.txt` | The endpoint definitions witnessed from the compiled classes and handed to FlowDroid. |
| `pysa-python/resolved-models.pysa` | The committed model template resolved against the fixture's module. |

**The fixtures are not cases.** They carry no `case.json`, no template
identity, no polarity and no score tier, they live outside `cases/`, and no
population, denominator or freeze sees them. They are generated by the runner
from templates in its own source and retained here so a reader can see exactly
what was analyzed.

## What is and is not in a number

- **FlowDroid's APK materialization is excluded**, exactly as
  [A12](../../../docs/latency-tier.md#amendments) excludes it from every cold
  FlowDroid number: the two compiles, the D8 dex translation and the stored-zip
  assembly all happen before the timed subprocess is spawned.
- **Fixture materialization is excluded** for every adapter, by the tier's
  standing exclusion list.
- **CodeQL and Infer are timed per declared phase and summed**, as their cold
  whole-invocation figures are, and both phase values are retained.

## Reproducing one

```bash
cargo run -- estimate-invocation-overhead --tool <adapter> --language <language> \
  <the same distribution flags that adapter's kernel runner takes>
```

Each arm witnesses its distribution's pinned identity through the same function
its kernel runner uses, so a wrong jar, binary or virtualenv refuses the
measurement rather than producing a number attributed to a distribution the
runner never verified.

Measurements run sequentially, and each waits for the machine's load to settle
before it begins — nine heavy analyzers run back to back drive the load average
up by themselves, and without the wait a later measurement would record
conditions its own predecessors created rather than the machine's.
