# v0.9.0 whole-corpus release contract

This prospective registration is not a release or a score activation. It adds
an explicitly selected `--population v0.9.0` execution population while retaining
the default corpus and every historical population, report, outcome and freeze.

## Population and report scope

The population is exactly the 1,000 cases bound by v0.8.0 plus the 108 immutable
`swift-synthetic-v3` cases: 1,108 unique cases across 14 languages. It includes
the four opaque Swift inputs outside `cases/`. Its common fixture revision is
`sha256:7c8619b2d4a93467fd0a502ed03668bfc8f3b9878a7bd5e9271c7aca31f75f62`.
`populations/v0.9.0.json` binds case and fixture hashes.

`reports/releases/v0.9.0/plan.json` registers exact membership for 92 report
partitions and 4,252 rows. It preserves the existing 82 partitions and adds five
Swift partitions each for CodeQL and Joern. Bifrost Swift is unsupported; no
fictional Bifrost Swift execution or reserved-track activation is introduced.

All reports must come from fresh execution or prospectively bound unsupported
capability decisions under the common revision. Historical reports are references,
never new-run evidence, and their fixture revision must not be relabeled. Keep
runner-error, inconclusive and unsupported distinct; none is a negative. Retain
all failed attempts and bind normalization to independently verifiable raw bytes.
The Darwin aggregate-resource limitation remains visible in Swift outcomes.

## Execution review and resources

The plan remains non-executable until the parent reviews the exact commands,
pins, query/rule/model identities, controls and acquisition/storage budget.
The authorized scope is the full normal release route, including necessary fresh
matrix evidence, freeze and publication. Generic scope approval is not repeated.

Run one analyzer serially. Ongoing Bifrost work has priority, including its
uncontended performance slot. Do not infer availability merely from a process
snapshot. Current #3735 reservation is active as of the September 29 review.
Before restoration, account for compressed downloads, extraction scratch,
installed tools and retained output. Require at least 64 GiB free after tool
restoration: 40 GiB reserve plus 24 GiB CodeQL scratch. Recheck before each lane;
pause safely if the reserve or exclusive slot is lost. Preserve shared caches,
active/warm targets and all hash-bound evidence.

Historical wall timestamps suggest 17.73 hours for one serial correctness matrix,
including each multi-partition Swift run once. This is a diagnostic cost estimate,
not a promised runtime or qualifying uncontended measurement. The initial budget
is 28.6 hours including 50% timing contingency and two setup hours; separately
resolve controls, repeats and acquisition before making the plan executable.
CodeQL dominates the historical cost (15.82 hours). Do not silently start an
unbounded retry loop or relax cutoffs to fit the budget.

New outputs belong under the versioned release namespace. Existing harnesses
that write fixed report/raw paths require isolation or versioned output support
before execution; never replace bytes referenced by prior freezes. Swift normal
v1 scripts and plans are hash-bound historical inputs and require a new versioned
common-population integration, not edits behind their existing hashes.
