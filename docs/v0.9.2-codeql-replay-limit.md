# CodeQL Swift replay limitation for v0.9.2

The current CodeQL Swift qualification evidence is replayable on the capture
host only while its original worktree remains available at
`/Users/dave/.codex/worktrees/9f01/dataflowbench`. The raw records in
`reports/releases/v0.9.2/qualification/codeql-swift-common108/control-attempt-02/`
bind that absolute `capture_root` and per-control `capture_output_dir`. The
frozen verifier checks both the copied evidence and the original capture-root
files by digest, and requires the original capture directories to exist. The
`query-check-02/receipt.json` similarly binds the absolute `execution_root`
and the verifier rereads query, command, and output copies from it.

Command arguments, working directories, query paths, and runtime paths in these
receipts are historical facts about where the controls ran. A fresh release
snapshot may retain byte-identical copies at the same relative evidence paths,
but relocating that snapshot does not rewrite those recorded values or remove
the verifier's dependency on the original worktree. If the original worktree is
missing or inaccessible, replay fails closed; the copied files alone do not
currently establish a portable replay.

Keep the exact captured Swift source fixtures under each registered control's
`source/` directory in the committed qualification evidence, and include those
files in the explicit release `source_inputs` closure with their captured
SHA-256 values. This preserves the inputs in fresh source snapshots without
including generated databases or other extraction outputs. The copies support
evidence retention; they do not satisfy the frozen verifier's original-root
checks.

Portable replay remains a separate verifier change. It would need to validate
the digest-bound copied evidence while treating original `argv`, `cwd`, and
absolute paths as recorded historical strings, without executing them or
requiring the capture host's directory tree. This v0.9.2 evidence makes no
claim that such a verifier has been implemented.
