# v0.9.1 Bifrost release refresh

This patch release measures the public Bifrost v0.13.0 release against the
unchanged v0.9.0 population. Its 1,108 cases, case and fixture bytes, expected
behavior, 92 report partitions and 4,252 report rows remain fixed. Every run
selects `--population v0.9.0`, with fixture revision
`sha256:7c8619b2d4a93467fd0a502ed03668bfc8f3b9878a7bd5e9271c7aca31f75f62`.

The dated [pin review](releases/v0.9.1-pins.md) precedes execution. The official
macOS release archive, publisher checksum, binary digest, build identity and
crates.io publication metadata are retained under
`reports/releases/v0.9.1/acquisition/`. The benchmark uses the publisher's
binary, whose build identity is witnessed; the crates.io package is independently
verified as published and not yanked.

All 20 Bifrost report partitions are refreshed: the cross-language smoke slice,
13 language kernels, three controlled modeling partitions and three native
partitions. Together they contain 1,116 report rows, including overlapping
smoke/kernel membership. The other 72 partitions, containing 3,136 report rows,
carry over byte-for-byte from the v0.9.0 freeze. Their original paths, versions,
fixture revision and raw evidence remain their provenance. Carry-over is not a
claim that those tools were executed again.

The public v0.13.0 engine no longer embeds product rules. Native qualification
must verify its empty shipped catalog and explicit no-rules evaluation state.
The native partitions retain `unsupported` outcomes under a new version-specific
capability rationale. Host-acquired Bifrost-packs rules are a separate
configuration; the benchmark does not silently substitute them. Controlled
partitions continue to supply the existing benchmark policies. Their model-on,
model-off, sanitizer and near-miss controls require completed evidence before
the matrix starts.

The strict first qualification remains failed and immutable. A separate retained
control review binds all 44 invocations and their original bytes. It verifies
36 complete policy runs, including all 15 sanitizer controls, and exactly three
JavaScript `partial_discovery` runs against the semantic states and raw digests
of the v0.9.0 freeze. Those three remain inconclusive. Fifteen complete controls
retain typed `empty_selection` advisories and endpoint counts proving that a
source or sink was unbound; their zero findings are vacuous, not clean negatives.
Native stdout explicitly records `not-evaluated` / `no-active-rule-packs`.
This review permits measurement under the existing outcome rules; it does not
claim full policy qualification, and no expected benchmark outcome is changed.
The executor recomputes the review before starting the matrix. Any new or changed
limitation, unexpected diagnostic, missing artifact, or failed sanitizer control
blocks execution.

Execution series 01 stopped before analyzer dispatch because its source snapshot
omitted the corpus metadata required during runner setup. Its plan, ledger and
failed C receipt remain immutable. Series 02 adds those committed corpus and
review-document inputs, first verifies full setup in a fresh source snapshot,
and uses new execution/cache roots, `attempt-02` receipts and `ledger-v2.jsonl`.
It still permits only one attempt per group and never retries automatically.

Execution uses an exact committed runner source and SHA-256-bound binaries.
Each group runs serially in a new source-only workspace, retains original
reports and raw bytes, and stages a versioned normalized report by remapping only
`raw_output`. Receipts bind commands, environment, source and tool identities,
membership and captured file digests. Attempts are never overwritten or retried
automatically. Timeouts, incomplete analyses, unsupported cases and runner errors
remain distinct outcomes. Existing freezes and their evidence remain immutable.

Before each group, require the common analyzer lock, no competing build or
analyzer processes, and at least 64 GiB free. Use a task-owned
`BIFROST_CACHE_ROOT`. Retained cold timings describe these executions; they do
not certify a performance improvement against v0.12.0. Any uncontended
performance comparison requires separately registered matched measurements.

The [freeze lifecycle](freeze.md#freeze-lifecycle) remains the delivery gate:
merge fresh evidence first, create the new freeze from clean merged main, then
submit freeze and generated results separately. A release tag, canonical release
notes and Pages publication follow validated merged artifacts. The current
v0.9.0 publication remains the active snapshot until that sequence completes.
