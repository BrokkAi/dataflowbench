# DataFlowBench v0.9.1 Bifrost native capability amendment

This versioned appendix amends the Bifrost row for the v0.9.1 refresh. It
applies only when the run witnesses the exact version line `bifrost 0.13.0`.
The historical `docs/native-profile.md` contract and the v0.9.0 native reports
remain unchanged.

## Evidence and identity

The standalone public release's native activation is recorded as:

> standalone engine; no active product policy packs

The acquisition evidence is retained in:

- `reports/releases/v0.9.1/acquisition/builtin-policy-catalog.json`, whose
  schema version 2 catalog has `packs: []`;
- `reports/releases/v0.9.1/acquisition/help.txt`, which records the CLI's
  host-supplied policy-pack boundary; and
- each refreshed report's `tool_version` and `tool_build_identity`, witnessed
  from the invoked binary's `--version` and `--build-identity` surfaces.

The activation passes the existing standalone `--policy` surface with no
`--policy-file`, selector, private pack, or host pack installation. The
acquisition catalog, CLI evidence, this appendix, and the witnessed binary
identity are part of the v0.9.1 execution evidence snapshot used by the
release executor.

## Capability decision

The v0.13.0 standalone engine ships no product policy rules. Consequently all
six native templates remain in Bifrost's `unsupported` partition for Java,
JavaScript, and Python. No native fixture is handed to the analyzer and no
successful native coverage is inferred from the empty result.

An empty native partition is `unsupported`, not a clean `not-reached` negative.
A host configured with Bifrost-packs is a separate product profile; it is not
benchmark-invented model input and is outside this release amendment.

The amendment is deliberately version-scoped. A later Bifrost version must
provide fresh catalog, CLI, version, and build-identity evidence before its
native capability classification changes.
