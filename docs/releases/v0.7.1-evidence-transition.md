# v0.7.1 publication validation

The pin and measurement evidence survived squash merge as
`2007f15d687e0081c948e55bba39c952d248ee0f`. The release manifest records that
exact revision. The temporary v0.7.0 historical-checkout CI step is removed:
current reports and current generated results must now validate together.

`check-release-results.py` is deliberately scoped to v0.7.1 and this evidence
revision. A later release must deliberately update the gate and its tests.
All formatting, Rust tests, corpus/report validation and site gates remain.

The gate requires a clean committed checkout and creates a disposable,
independent clone with full history and isolated object/tag storage. Successful
fetches from the actual GitHub repository must precede any missing-tag
inference. It proves the fixed evidence revision is an ancestor of fetched
main and checks the manifest's release identity.

If v0.7.1 exists, the gate never changes it: it must contain the evidence
revision and its manifest/results must match the current committed tree. If
absent, only the disposable clone receives a local tag at its HEAD. Ordinary
`validate-freeze` and `generate-results --check` then run without bypassing
semantic, digest or ancestry checks. The clone is deleted. No tag is pushed.
Fetch failure, unknown tag state, wrong evidence identity/ancestry, or an
existing mismatched release tag fails the gate.

For initial artifact generation, the same isolated gate runs from a clean
manifest commit with `--generate-output` targeting an external directory.
Generated artifacts are copied to the publication branch and committed; the
full check runs again against that final tree. Normal worktrees and remotes
never receive a provisional tag.

After the final PR is squash-merged, the publisher creates the remote release
tag once at the surviving manifest/artifact commit. That tag contains the
frozen evidence ancestor. Publishing and merging require parent coordination;
this workflow has no push or publication action. Never move a published tag.

The v0.7.0 archive remains pinned to its actual published manifest commit
`61300f47de7affa651fbd4a125ca6b894b29ce71`, rather than its earlier evidence tag.
