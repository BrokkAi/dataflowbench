# v0.7.1 evidence transition

The pin and measurement PR refreshes current report paths before the separate
release manifest PR can name its surviving merge commit. During that interval,
`reports/freeze.json` and `results/` still describe published v0.7.0.

CI keeps current-checkout formatting, tests, corpus validation, report
validation and site checks. Its temporary final results step requires a clean
checkout and byte-identical `reports/freeze.json` and entire `results/` tree
against `61300f47de7affa651fbd4a125ca6b894b29ce71`. It then runs the ordinary
results check using that historical source in a separate clean detached Git
worktree under `RUNNER_TEMP`. Full checkout history and tags are shared with
that worktree. No current report failure is exempted, no historical manifest
is rewritten, and no development manifest names evidence absent from its
recorded revision.

`61300f47` contains the published release manifest. The v0.7.0 tag at
`0a4d8b66` names its evidence commit and still contains development-scope
results. Site archives therefore use the former for published manifest and
result links, while the benchmark baseline remains the latter.

After the evidence PR merges, create the v0.7.1 freeze from a clean checkout
of its surviving merged revision, selecting `--population v0.7.0`. The separate
manifest PR must replace the temporary CI step with:

```yaml
- run: cargo run -- generate-results --manifest reports/freeze.json --output-directory results --check
```

That PR also generates the validated release artifacts and site bundles and
assembles the hashed auxiliary inventory. The temporary byte guard and the
site regression test reject a new manifest while the historical CI step
remains. Remove the transition step rather than updating its historical hash.
The old release's archive bytes and manifest-containing evidence reference
remain pinned. This transition is preparation, not a v0.7.1 release claim.
