## Portable acceptance gate

```sh
python3 -B scripts/v092_timing_publication.py verify --root .
python3 -B scripts/test-v092-timing-publication.py
python3 -B scripts/v092_timing_publication.py stage-site --root . --output docs/public/evidence/timing/v0-9-2/20261113-v1
```

The verifier restores the original lossless bundle into a temporary directory
under its `snapshot/` prefix. It checks the captured inputs and supplies the
hash-verified frozen publication manifest and baseline reports. The retained
reconciliation program then runs against that restored tree. Its summary,
per-case records, and evidence manifest must reproduce the original bytes.
This operation reads evidence; it launches no analyzer and requires no existing
local `execution-state` tree. The absolute capture-host path inside the original
retention receipt remains acquisition provenance, not a reproduction root.

The site renders numbers from that retained reconciliation. It reports the
completed and blocked coverage, unsupported rows without invented timings,
inconclusive outcomes, contention and settling limitations, and unproven
descendant containment. Overhead estimates stay separate from cold case
distributions and from the unmeasured warm marginal tier. No relative or
cross-release performance claim is made.

## Website delivery

The versioned page is
`/snapshots/v0-9-2/timing-20261113-v1/`. Its download root is
`/evidence/timing/v0-9-2/20261113-v1/`. Downloads include the publication manifest,
original reconciliation files, and original compressed evidence bundle, all
with retained SHA-256 bindings.

The compressed file index is served as `evidence-v1/files.jsonl.gz.bin`, with a
browser download name of `files.jsonl.gz`. This prevents static servers from
treating the archive as transport compression and silently changing the bytes
delivered to a browser or Fetch client. Save that file with the bundle's original
`files.jsonl.gz` name before verification or restoration.

The archival tag `evidence/timing/v0.9.2/20261113-v1` retains the original capture
commit independently of the website publication merge. It does not move the
product's `v0.9.2` tag or certify the timing observations.

CI and the manual Pages workflow run the timing gate before building the site.
Require successful PR CI, merge through the ordinary repository workflow, and
verify exact merged-main CI before dispatching **Deploy site** from main.
Wait for terminal build and deployment success, then verify the live supplement,
its navigation links, and downloaded manifest/data/bundle bytes against their
recorded hashes. A successful workflow dispatch alone is not publication proof.
