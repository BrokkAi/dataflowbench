# v0.9.0 common-population execution integration

The merged preparation plan is immutable. `reports/releases/v0.9.0/execution-v1`
contains the next prospective contract; its integration-in-progress status does
not authorize analyzer execution. Parent review follows completed exact command,
identity, membership, retry and resource registration.

All groups run serially in one isolated execution checkout. Legacy adapters keep
their original relative output paths there. Fresh output is captured under a
unique attempt namespace, original normalized bytes are retained, and a separate
normalized publication projection changes only raw-output paths to the retained
namespace. Raw bytes and their nested hash-bound references are never rewritten;
replay resolves them against the captured execution root. A failed attempt remains
retained and cannot become a successful row through a later overwrite.

The five Swift partitions per tool share one 108-case execution. New versioned
wrappers validate the entire 1,108-case manifest before selecting its exact Swift
projection, preserving the full common revision. Historical v1 engines, semantic
queries, budgets and normalization remain unchanged and independently replayable.

The freeze constructor must include the same registered opaque root as ordinary
case discovery. Otherwise the four opaque Swift cases are visible to the runner
but unknown when constructing the freeze. This is an input-indexing correction,
not a new fixture or a changed expected outcome.

## Environment and resource boundaries

The held Semgrep environment's launcher appends its scripts directory to PATH.
With a system `pysemgrep` first, its fallback reports 1.176.0 while the held core
reports 1.177.0. The versioned environment prepends the exact held venv, preserves
remaining dependency search paths, and disables the version check. Both live
witnesses then report 1.177.0; the historical environment is not modified.
A regression checks that a stale system fallback cannot win and unrelated
required executables remain discoverable.

The provisional launch floor is 100 GiB: 40 GiB protected reserve, 24 GiB scratch,
24 GiB total new retained evidence allowance, and 12 GiB checkout/staging. Existing
historical evidence and tool installations are already outside this incremental
budget and remain preserved. All held external tool paths are present; no new
installer download is planned. Recheck identity and capacity before launch and
each group. Stop before starting another group if reserve, retention ceiling or
exclusive ownership cannot be met. Swift CodeQL's last full retained run occupies
about 5 GiB and Joern's 0.16 GiB; these are planning observations, not guaranteed
peaks. The two-attempt bound does not authorize retries to improve outcomes.

CodeQL 2.27.1 is required for every new CodeQL partition. Its held non-Swift query
pack tree is inventoried exactly and checked for compiler compatibility in a
separate scratch directory without modifying historical queries or packs. Query
checking is not corpus execution or evidence of analyzer accuracy.

## Registered command and capture boundaries

The integration contract now records 84 exact argument arrays and complete child
environments, mapping their outputs to 92 named report partitions. Non-Swift
commands differ from the immutable preparation plan only in the built harness
path and the common CodeQL 2.27.1 path. The Swift groups call the versioned
wrappers and map the five exporter ordinals explicitly. The checker rejects
changed membership, mixed CodeQL versions, altered command arguments and shorter
deadlines. Planning validation always reports `executable: false`.

The child environment binds Temurin 21.0.8 through `JAVA_HOME` and PATH. macOS's
`/usr/bin/java` launcher alone is not a JDK identity and fails without that
selection on this host. Dependency witnesses record Java, javac, Kotlin, Python
and Go under the actual explicit environment. Semgrep adds its held venv first.

A report row's `raw_output` is a path; result/v1 does not require a `raw_sha256`
field. Capture inventories bind those raw bytes. Any optional embedded digest
must agree, but absence of that field must not invalidate an otherwise valid
report. The original normalized bytes remain retained alongside the publication
projection so outcome and identity changes can be rejected independently.

## Integration validation

The complete Rust suite passed 286 tests and the optimized harness validates
1,108 selected cases and 92 retained historical reports. All 84 prospective
commands passed argument parsing with `--help`; that is not analyzer execution.
The existing CodeQL v1 and Joern v1 runner suites passed 16 and 12 tests,
respectively. These checks establish integration behavior only; they do not
substitute for the fresh common-revision matrix, controls or release freeze.


The root preparer uses the exact merged harness and a separately committed,
reviewed descendant plan. It removes declared legacy output roots only from the
new execution checkout. The source checkout and historical bytes stay intact.
One central checkout keeps the attempt limit shared across the whole matrix;
an existing destination cannot be recreated to reset that limit. The tracked
harness tree measured about 0.71 GiB during preparation, so 84 full checkout
copies are unnecessary.

The common Joern activation bridge first runs the original v1 verifier against
plan 04 and its retained controls. It then checks an exact permitted change set:
common population identity, versioned wrapper references and output root, and
prospectively rebound unsupported decisions. Runtime, queries, models, phase
budgets, capabilities and original activation evidence stay byte-bound. Fresh
CodeQL resolution/check-only qualification passed all 12 Swift queries against
the common plan. These are compatibility checks, not matrix outcomes.
