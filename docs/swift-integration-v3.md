# Prospective Swift integration v3

This staged boundary keeps semantic observations separate from admission under
canonical execution budgets. It activates no scored adapter and changes no
historical report, population, freeze, or published denominator.

`swift_integration_v3.normalize_population` preserves every selected case,
rejects duplicate or foreign observations, and retains raw observations alongside
normalized outcomes. Missing endpoints, extraction failure, missing executions,
and uncertain cleanup are runner errors. A recorded timeout with completed
cleanup remains inconclusive with `BudgetExhausted`. Persistence requires the
initialized-key coverage output and an explicit expected-scope inventory;
missing, unknown, or incomplete coverage cannot produce a clean result.

Aggregate resource qualification remains unavailable. The current Darwin runner
explicitly records incomplete descendant discovery and unproven containment.
The normalizer therefore admits no definitive reached/not-reached results,
even when queries succeed or an input claims resource qualification. The
canonical 60-second/512-MiB contract is compared independently with diagnostic
budgets. This helper is an integration boundary, not a certificate verifier or
a replacement for the pending production runner. Caller-provided endpoint and
scope fields still require binding to verified raw artifacts by that runner.

The separate `swift-opaque-v3` staged population contains four prospective
fixtures for the approved Darwin-only opaque and positional templates. Its
runtime dispatch class is byte-identical to the qualified prototype. Functions
hold the analysis endpoints to avoid the retained top-level CFG limitation;
the final call permits subsequent bounded runtime validation. The undeclared
`block` sibling intentionally propagates at runtime: its negative expectation
concerns declared-model activation, not sanitation. The positional negative
passes taint only in argument zero while the model propagates argument one.

These files live under the versioned population while qualification proceeds.
They are not yet registered in canonical `cases/` discovery. This preserves
historical validators and makes the missing registration explicit. A successor
must compile/runtime-check these exact fixtures, establish exact canonical
model-off/on evidence, bind the new population and query/runtime closure,
then register the fixtures with version-aware historical validation. No
prototype result is relabelled as canonical evidence.

Remaining dependencies are the composed resolved adapter queries and runner,
canonical opaque activation, common final population, actual aggregate resource
qualification, fresh common-revision reports, and the normal freeze/publication
gates. Bifrost Swift remains unsupported; Joern's unresolved identity gap remains
separate from CodeQL's adapter-assisted work.
