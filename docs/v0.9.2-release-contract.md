# v0.9.2 full analyzer refresh

This patch release refreshes all eight analyzers against the unchanged v0.9.0
population: 1,108 unique cases, 84 serial execution groups, 92 report partitions
and 4,252 report rows. Case bytes, fixture bytes, expected behavior, profile
boundaries and execution budgets remain fixed. All eight analyzers execute
again, including engines whose latest stable release is unchanged. No prior
report is carried forward as fresh execution.

The prospective [pin review](releases/v0.9.2-pins.md) names the current release
and package acquisition targets. Official metadata, publisher checksums,
acquisition receipts, environment inventories and new controls are retained
under `reports/releases/v0.9.2/`. Task-owned runtime assets live under
`execution-state/v092/`; they are required execution inputs, not disposable
cleanup targets. Previous evidence, failed attempts and freezes stay immutable.

Bifrost 0.13.1 introduces external pack auto-acquisition. This refresh preserves
the existing explicit-policy and shipped-catalog configuration by setting
`BIFROST_OPEN_PACKS_DISABLE=1`. Acquiring an external rule or semantic pack would
constitute a separate configuration. The first control attempt fails before
policy dispatch because the isolated environment has no host acquisition cache;
that attempt remains retained. The second attempt changes only this registered
environment boundary. Its strict schema-5 qualifier remains failed. A separate
schema-6 review verifies all 44 invocations and their byte inventories, 36
complete policy runs, 15 sanitizer controls and 15 unbound-endpoint controls.
Three JavaScript runs retain `partial_discovery`, now with explicit file scopes;
positive finding proofs improved, but the runs remain inconclusive. No empty
selection or empty native catalog is interpreted as a clean result.

CodeQL and Joern Swift require fresh runtime, extraction, query, activation and
resource qualification. Their old temporary runtime paths and old patched
extractor hashes cannot establish compatibility with current releases. A
successful patch application is compatibility evidence only. Fresh source,
compiler resources, patched schema, query packs, commands and resulting binary
identities must be bound before selecting a Swift execution group.

The frozen CodeQL control replay requires its preserved original capture root
on this host as well as the copied, digest-bound evidence. The
[replay availability limit](v0.9.2-codeql-replay-limit.md) records this
explicitly; this refresh does not establish portable replay on another host.

Fresh Semgrep CE 1.181.0 controls establish local model activation and parsing
of the selected Java, JavaScript and Python native rule snapshots, with a
positive and a near miss for each profile. A separate C# probe also detects a
direct taint flow and rejects an unrelated-value negative. C# remains outside
this fixed refresh as an unadapted profile pending separate preregistration;
an old Pro-only limitation is not a current capability claim. Remote
registry-lints validation failed independently and remains recorded.

Every group uses a fresh attempt namespace, captures native bytes and original
normalized output, and creates a separate publication projection that changes
only retained evidence paths. A failed attempt is never overwritten. Exact
binary/component identities and qualification scope are rechecked before
execution; the common analyzer lock permits one analyzer at a time. Require at
least 127 GiB free before launching each new-target group, maintain the 125 GiB
continuous floor, and preserve the protected disk reserve, retention ceiling
and existing per-case budgets. Do not infer soundness,
cleanliness or comparative performance from incomplete or contended results.
